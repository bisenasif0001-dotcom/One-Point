# Step 6 — local document workflow

Checkout shows the selected catalog service's required files and optional files separately. Generic identity/photo placeholders are removed. Known document requirements are preserved; an empty or unknown policy is explicitly left for operator confirmation and is not treated as a no-document exemption. Existing upload-now or send-later choice remains available. Required proofs still need operator review before fulfilment.

Selecting a checkout file no longer shows simulated upload progress. Files remain selected in browser memory and are sent as real bytes after the backend creates the order, before the gateway opens. If transfer fails, the existing order remains usable for payment and the customer can retry its files from the order page; no automatic duplicate booking is initiated for an upload failure. Selected files cannot survive a browser reload; use the later-upload page to reselect them.

`order-documents.html?order=<ID>` links later submission to the correct order. It shows catalog requirements, actual file records and document status; it offers authenticated upload and an order-referenced WhatsApp assistance link. Login returns to this page. Successful payment and account order details include a send/retry link. Unknown explicit order IDs no longer fall back to the first account order.

PDF/JPG/PNG uploads use a consistent 3MB-per-file limit, with request size, extension and content-signature validation on the backend. The owning customer session and CSRF token are required. Real files are stored under backend/uploads/customer-documents with generated filenames; backend files cannot be served by the public static handler, including Windows case variants. File hashes make a same-order retry idempotent. The legacy metadata endpoint now also requires ownership; filename-only records are labelled as missing content rather than confirmed uploads.

Document state is separate from payment state: `awaiting_documents` means file content is missing; `awaiting_review` means real files were received. Neither automatically declares all requirements satisfied or the request ready for processing. Operator document coverage/review and final service-specific deferral rules remain part of fulfilment configuration. Old records without real file content are not retroactively counted as uploaded. This pilot does not waive any service's requirements or implement an unapproved no-document rule.

Validation: isolated real HTTP/database test with a simulated gateway covers checkout-selected bytes, later browser upload, ownership, CSRF, content signature, private storage, duplicate retry, interrupted upload recovery, correct applicant invoice and payment/doc-status separation. Checkout and document page geometry are checked at 320, 360, 375, 390, 414, 430, 600, 768, 1024, 1280 and 1440px. Use `npm run test:documents`, `npm run test:ux`, policy/routing checks and normal syntax checks.

No live deployment, real gateway charge or physical-phone camera/Safari verification was performed. The regular preview remains read-only; real upload tests run in a disposable local backend copy. Later deployment must retain and back up the backend uploads folder alongside the database.
